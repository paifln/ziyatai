# Переход на Supabase

Приложение использует Supabase Auth с email и паролем, приватную PostgreSQL-схему и приватный Storage bucket. Шаблоны писем и настройка URL описаны в основном README. Пароли предыдущего провайдера не переносятся.

## Подготовка

Создайте игнорируемые файлы окружения источника и назначения. Назначение заполняется по `.env.supabase.example`; секреты хранятся только локально или в secret manager. Сначала выполните `npm run supabase:check -- .env.supabase.local`.

До копирования сохраните PostgreSQL dump и резервную копию файлов. Остановите записывающие web и worker источника; дождитесь завершения активных задач. Не запускайте одновременно старую и новую систему с независимыми базами после переключения.

Для нового пустого проекта `scripts/supabase/build-bootstrap.ts` собирает исходные миграции в `.local/supabase-bootstrap.sql`. Применяйте его только к пустой схеме. Для последующих изменений используйте `npm run migrate`, сохраняя исходные контрольные суммы.

## Копирование

```powershell
npm run supabase:copy-db -- --source-env .env.source.local --target-env .env.supabase.local
npm run supabase:copy-files -- --source-env .env.source.local --target-env .env.supabase.local
```

Проверьте результат предварительного запуска. Для записи добавьте `--apply --maintenance`. Скрипт базы сверяет количество строк и контрольные суммы внутри согласованной транзакции; уже заполненное назначение отклоняется. Сессии и пароли старого провайдера не копируются. Скрипт файлов проверяет SHA-256 и не перезаписывает существующий отличающийся объект.

## Проверка и переключение

Проверьте приватность bucket и схемы, доступность renderer/антивируса, запустите `scripts/supabase/auth-smoke.ts` против нового backend. Проверьте реальное письмо подтверждения/восстановления, импорт КТП, генерацию, одобрение и скачивание DOCX/PDF. Затем переключите Netlify proxy на новый backend и запустите единственный worker назначения. Сохраните источник и резервные копии до завершения приёмки.

Синтетические проверки авторизации не подтверждают реальную доставку почты. До настройки SMTP в Supabase встроенный отправитель ограничен адресами команды проекта. Перед переключением повторно синхронизируйте данные, если источник продолжал принимать записи после первоначального копирования.
