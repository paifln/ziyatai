# Netlify и backend на ноутбуке

Подготовлено 2 ноября 2026 года. Railway и другие платные серверы для этого режима не нужны.

Интерфейс размещается на https://ziyatai.netlify.app. API, PostgreSQL, worker, renderer, ClamAV и приватное Garage-хранилище работают в Docker Desktop на этом ноутбуке. Два Cloudflare Quick Tunnel обеспечивают HTTPS для API и подписанных загрузок файлов. БД, renderer, почтовый тестовый ящик и антивирус через туннели не публикуются.

Сервер принимает бизнес-запросы только с подписью Netlify. Браузер загружает файл прямо в приватное хранилище по ограниченной подписанной ссылке. CORS допускает origin сайта Netlify. Синтетическое демо отключено, антивирус обязателен. Настоящий OpenAI оплачивается отдельно. Внешний SMTP не подключён: регистрация без проверки почты, восстановление пароля недоступно.

## Управление на подготовленном ноутбуке

Откройте PowerShell в корне репозитория. Перед запуском включите Docker Desktop.

Также можно дважды нажать `Start online.cmd` для включения и `Stop online.cmd` для остановки.

```powershell
node scripts/laptop-backend.mjs status
node scripts/laptop-backend.mjs start
node scripts/laptop-backend.mjs stop
```

`start` использует отдельную конфигурацию `.local/hosting/laptop-backend.env`, запускает инфраструктуру и включает `infra/compose.laptop.yml`. Исходная `.env.local` остаётся для локальной разработки. `stop` проверяет, что очередь завершена, затем останавливает сервисы и туннели; постоянные диски не удаляет. Старый режим `Start demo.cmd` не следует запускать одновременно с публичным режимом, поскольку оба используют одну БД и очередь. Скрипт предупреждает об отдельном запущенном локальном worker, но не прерывает работу других чатов автоматически.

Quick Tunnel выдаёт новый адрес после перезапуска. `start` обнаруживает смену адресов, обновляет CORS/настройки backend, пересобирает и публикует Netlify. Это занимает несколько минут и расходует квоту deploy Netlify. Ссылка самого сайта Netlify остаётся прежней. Для постоянных адресов потребуется отдельная настройка именованных туннелей со своим доменом.

Команда запуска рассчитана на уже подготовленные локальные образы `ziyatai-web:laptop`, `ziyatai-worker:laptop`, `ziyatai-renderer:laptop`, контейнер Linux-сборки `ziyatai-netlify-build` и авторизованный Netlify CLI. Она не является установщиком для нового компьютера. Не удаляйте сборочный контейнер до переноса сборок в CI. В `/build` этого контейнера находится проверенный снимок исходников; команда публикует этот снимок, а не автоматически все последующие правки рабочей папки.

Для повторной публикации уже подготовленного снимка без перезапуска backend:

```powershell
node scripts/laptop-backend.mjs publish
```

Сборка Netlify выполняется внутри Linux-файловой системы контейнера. Нельзя монтировать `.next` отдельным томом: OpenNext переименовывает эту папку при упаковке.

## Ограничения

- Ноутбук должен оставаться включённым, без сна, с работающими Docker Desktop и интернетом. После выключения backend недоступен; frontend на Netlify остаётся.
- Quick Tunnel предназначен для тестирования и не гарантирует непрерывную доступность. Для апробации на Railway нужно будет отдельно проверить облачную конфигурацию.
- Локальное хранилище и БД используют существующие постоянные диски. Резервные копии храните отдельно от ноутбука. Не используйте `docker compose down -v`.
- До приглашения участников заполните `LEGAL_CONTACT_EMAIL` и проверьте имя оператора в локальных frontend/backend-настройках, затем выполните `publish`. Секреты и env-файлы не публикуются в Git.
- Отдельный worker удаляет просроченные quarantine-объекты. Пока ноутбук выключен, очистка откладывается.
