# Эксплуатация

## Проверка готовности

`node scripts/deploy/laptop-backend.mjs status` проверяет контейнеры и публичный `/api/health/ready`. Liveness подтверждает работу API; readiness — доступ к БД, Storage и свежий heartbeat worker. Это не проверка доставки почты, качества AI или всей цепочки экспорта.

При 503 проверьте Docker Desktop, интернет и состояние контейнеров. Затем доступность Supabase, приватного bucket, renderer и ClamAV. Не выводите заполненные env-файлы или полные ошибки провайдера в публичные логи.

## Обновление

1. Выполните проверки из README и дождитесь зелёного CI текущего коммита.
2. Перед изменением схемы сделайте резервную копию; дождитесь завершения записывающих задач и остановите web/worker.
3. Примените новые миграции одним runner: `npm run migrate` с окружением целевой БД. Применённые миграции не редактируйте.
4. Пересоберите образы web/worker/renderer и запустите backend по [инструкции](laptop-hosting.md).
5. При изменении frontend опубликуйте чистый Git-коммит командой `node scripts/deploy/laptop-backend.mjs publish`.
6. Проверьте регистрацию, импорт и экспорт синтетического материала. `workflow-smoke.ts --fixture-export` не вызывает AI; настоящий AI-проверочный запрос требует отдельного запуска.

Остановка через `Stop online.cmd` проверяет очередь и отказывает при незавершённых задачах. Остановка контейнеров не удаляет Supabase или локальные резервные копии. При откате используйте совместимые образы предыдущего коммита; восстановление старой БД поверх новых записей не является безопасным откатом.

## Резервные копии

База и файлы резервируются отдельно. Уточняйте доступность и срок хранения managed backups в тарифе Supabase. Для независимой копии используйте логический PostgreSQL dump, отдельную копию приватных S3-объектов и защищённое хранение конфигурации. Секреты передавайте через окружение или secret manager, не через командную строку и Git.

Проверяйте восстановление в отдельный проект/БД: состав таблиц, количество строк, контрольные суммы, связность владельцев и наличие файлов. Проверка списка содержимого dump не доказывает восстановимость приложения. Сохраняйте исходник до приёмки назначения. [Скрипты переноса Supabase](supabase.md) выполняют сверку данных и не разрешают перезапись непустого назначения.

Ранее созданные `.local/backups/` и старые локальные Docker volumes сохраняются. Удаление исходников и старых отчётов не означает разрешения удалить эти данные.

## Секреты и фоновые задачи

Серверные ключи Supabase, S3 и AI не передаются Netlify frontend. При ротации меняйте согласованные backend/worker настройки; proxy secret должен совпадать с Netlify, renderer token — с renderer. После смены настроек пересоздайте контейнеры и проверьте готовность. `python scripts/checks/scan-secrets.py` проверяет отслеживаемые исходники без чтения игнорируемых секретов.

Worker обрабатывает очередь и очистку quarantine. При остановленном worker readiness ухудшается, а незавершённые задачи сохраняются в БД. Повторы используют lease и idempotency; внешний AI не имеет гарантии единственного платного обращения при аварии. Антивирус недоступен — загрузки остаются непроверенными и недоступными для импорта/скачивания.
