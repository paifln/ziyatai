# Приоритеты подготовки и запуска

## Работа над продуктом независимо от хостинга

Оплата блокирует только публичное развёртывание. Она не блокирует аудит, исправление дефектов, развитие архитектуры, безопасность, дизайн и проверку учительских сценариев. Прежнее утверждение, что все оставшиеся работы требуют внешних ресурсов, было слишком узким.

## Размещение: отложенные этапы

По указанию владельца оплаченные ресурсы и публикацию не запускать до оплаты. Проверенный код подготовки размещения — `75dc409`; обе GitHub CI jobs успешны. Результаты этого этапа: [hosting readiness](reports/hosting-readiness-2026-10-17.json), [read-only Railway plan](reports/railway-prepared-plan.json), [container scans](reports/hosting-container-security.json). Перечисленные ниже этапы размещения требуют оплаченного окружения, реквизитов или внешней экспертизы; работа над самим продуктом продолжается независимо от них.

| Приоритет | Работа | Критерий проверки |
| --- | --- | --- |
| P0, после оплаты | Проверить актуальный IaC plan, shared variables и ограничения расходов | Только ожидаемые добавления в отдельном ziyatai project; лимит подтверждён хостингом |
| P0, после оплаты | Приватный S3, CORS и quarantine sweep | PUT с точного frontend origin; unsigned GET запрещён; чужие данные недоступны; старый orphan удаляется |
| P0, после оплаты | Развёртывание пяти служб и Netlify gateway | Миграции, ready, worker heartbeat, подписанный proxy; API напрямую не обходит gateway |
| P0, после оплаты | Полный облачный сценарий | Регистрация без кода, импорт, класс, генерация, правка, одобрение, оба PDF-макета, удаление, повторный вход |
| P0, после оплаты | Backup и rollback | Восстановление БД и файлов в отдельное окружение; предыдущий app image запускается с совместимой схемой; destructive down-migration не используется |
| P1 | Измерить расход и пробуждение API/renderer/антивируса | Проверить первый upload/export после простоя, задержки и фактический расход; не обещать стоимость без измерения |
| P1 | Свежий scan точных production image digests | Зафиксировать версии базы CVE, findings и решения; старые container reports не переносить на новые digests |
| P1 | Публичный контакт и проверка применимых правил | Реальные согласованные реквизиты, проверка условий обработки данных и региона специалистом |
| P1 | Педагогическая экспертиза нескольких предметов | Оценка заданий учителями, сопоставление с целями исходника; автоматические тесты её не заменяют |
| P2 | Дополнить обезличенный корпус КТП | Сложные PDF и сканы, одиночные классы и объединённые документы; метрики точности и ручная проверка неоднозначных строк |

Локально закрыто: смешанные классы в исходном XLS, безопасное сохранение всех строк при фильтрации, серверный класс урока при генерации, mail-free signup в обоих интерфейсах, свободные шрифты, orphan quarantine cleanup, только безопасные GET/HEAD retries при пробуждении. Проверки и их границы отражены в отчёте, остальные требования не объявляются завершёнными по наличию кода.

Дополнительно `scripts/quarantine-sweep-check.ts` проверяет реальный ListObjectsV2 и удаление в локальном приватном S3: свежий объект сохраняется, просроченный orphan удаляется. Возраст задаётся внедрёнными часами только для одного собственного синтетического объекта; существующие файлы не меняются. Сценарий добавлен в Linux integration CI. Это проверка совместимого S3 протокола, не доказательство настроек будущего Railway bucket.
