# ADR 004: проверка учителем, гостевая главная и темы

Дата: 16 октября 2026. Статус: реализовано; внешний запуск проверяется отдельно.

## Решение

Раньше отметка учителя управляла надписью «Черновик», а файл можно было подготовить без неё. Теперь одобрение сохраняется в `generation_versions.reviewed_at/reviewed_by` и относится к конкретной версии. Endpoint `approve` проверяет владельца, текущую revision, отсутствие незавершённой перегенерации и структуру документа. Одновременно сохраняется свежий validation report, чтобы после одобрения не оставалось устаревшего предупреждения.

API экспорта требует серверное одобрение и соответствующую текущую revision; worker повторно проверяет одобрение экспортируемого snapshot. Передача одного `teacherReviewed: true` не позволяет обойти этот порядок. Правка, восстановление старого содержания и перегенерация создают новую версию без одобрения. Ранее одобренные файлы остаются доступными как история; они не меняются вместе с новым черновиком. Миграция сохраняет прежние явные подтверждения для исторических snapshots. Старые неподтверждённые файлы предлагают открыть задания для проверки.

Автоматическая проверка не подменяет учителя: она проверяет структуру, ссылки, баллы и ограниченный набор вычислений. Основной экран результата — карточки для чтения с раскрывающимися ответами и критериями. Редактирование и печатный макет вынесены в отдельные режимы. Скачивание PDF/DOCX открывается после явного действия учителя; генерация сама не создаёт печатные файлы.

## Даты КТП

`dateSkipped` означает осознанный пропуск даты. Пустое значение не заменяется выдуманной датой и не получает предупреждение `missing_date`, когда учитель явно выбрал пропуск. Массовая кнопка работает со всеми строками, независимо от фильтра, листа и пагинации. При наличии дат нужна проверка действия; до сохранения можно вернуть исходные даты, сохранив правки остальных полей. Lite поддерживает тот же формат данных.

## Главная и оформление

Гости видят знакомство с проектом и заранее подготовленные примеры по трём предметам; они обозначены как образцы. `/login` и `/signup` — прямые входы в формы. Cookie hint выбирает первый экран, но не авторизует пользователя: доступ к каждому личному ресурсу проверяет API. Гостевая главная появляется в серверном HTML до React hydration.

Светлая/тёмная тема использует локальную настройку устройства, сохраняется в `ziyatai-theme` и не отправляется как содержимое задания. Если выбора нет, используется тема ОС. Скрипт до первого отображения выполняется с CSP nonce; Lite использует отдельный ES5 скрипт без фреймворка. Печатные материалы остаются светлыми. Цветовые акценты — зелёный, янтарный и коралловый; добавление цвета не требует видео, WebGL или сторонних шрифтов.

## Эксплуатация

Основная схема — Netlify + Railway, описанная в [railway.md](../railway.md). Общий Dockerfile выбирает API или worker через публичный build ARG; API image содержит команду миграций. Renderer поддерживает dual-stack сеть. S3 signer поддерживает path-style и virtual-hosted endpoints, но наличие совместимого URL не доказывает поддержку CORS, lifecycle и размещения данных у выбранного провайдера.

Railway описан через новый `.railway/railway.ts`: пять служб, три тома, общие ссылки на секреты, отдельные роли сборки и миграция перед API deploy. SDK остаётся dev dependency. `check:railway` проверяет локальное описание и межсервисные ссылки; `check:deploy` — заполненные настройки каждого хостинга отдельно. Эти проверки не подключают аккаунт и не выполняют облачный plan/apply. Документация и скриншоты исключены из Docker-контекста, чтобы их изменения не пересобирали приложение.

Подготовка файлов показывает состояние очереди, допускает отмену и повтор. После повтора клиент обновляет и завершённые состояния, чтобы возобновить polling. При обычном ожидании он опрашивает только незавершённые операции. В renderer увеличено ограниченное ожидание font matching при холодном запуске; диагностика содержит этап, тип ошибки и длительность, без текста документов и credentials.

## Проверка и ограничения

Проверяются серверный запрет экспорта без одобрения, принадлежность версии, сброс после правки, обновление validation report, массовый пропуск дат, повтор отменённой операции, темы и доступность на разных ширинах. Локальный сценарий с настоящим OpenAI использует синтетический аккаунт и учебную тему. Его автоматическое подтверждение служит проверкой механизма; педагогическая экспертиза не выполнена.

Локальные проверки и offline Netlify packaging не доказывают работу DNS, CDN, реальной внешней почты, шрифтов и сетевых ограничений Railway. Для публичного запуска нужна отдельная приёмка на настоящих доменах. Модель и несколько постоянных backend служб не объявляются бесплатными.
