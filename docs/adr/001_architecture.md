# Архитектура ZiyatAI

Решение от 14 октября 2026 года: TypeScript, Next.js 16.4.0 и React 19.3.1; Node.js 24.21.0 LTS; Better Auth 1.7.7; PostgreSQL 18; приватный S3 adapter; отдельный worker; изолированный Python renderer/parser. Точные npm версии и install-script allowlist закреплены в package-lock.json. Проверены [Next.js installation](https://nextjs.org/docs/app/getting-started/installation), [Node.js releases](https://nodejs.org/en/download/), [Better Auth PostgreSQL](https://better-auth.com/docs/adapters/postgresql), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).

Для начальной нагрузки собственная простая PostgreSQL очередь использует транзакционную постановку вместе с бизнес объектом, FOR UPDATE SKIP LOCKED, lease, heartbeat и fencing token. Redis не нужен. Все проверки владельца идут на сервере; browser получает только разрешённые пользователю данные. SQL выполняется параметризованно; имена таблиц выбираются из фиксированных allowlists. Версии КТП и AST задания сохраняются неизменяемыми снимками. SQL DATE проекция создаётся триггером миграции.

Python выбран для pdfplumber/PDFium, OOXML, openpyxl и xlrd. OCR Tesseract использует kaz+rus только на проблемных страницах. Parser и LibreOffice в production вынесены в отдельный контейнер без OpenAI, БД и storage credentials, без сетевого маршрута в интернет и на отдельной внутренней сети. API требует отдельный длинный bearer token. Контейнер serial, unprivileged, read-only с ограниченными CPU/RAM/PID и временным каталогом. Владеющий очередью worker вызывает его для длительных операций.

DOCX строится библиотекой docx из валидированного AST. PDF получается из того же DOCX через LibreOffice. Fonts поставляет владелец на лицензируемом томе; отсутствие выбранного шрифта — явная ошибка, без подмены. Локальный тест использует установленные Windows шрифты только через read-only mount, они не включены в git или образ.

[Garage](https://garagehq.deuxfleurs.fr/documentation/quick-start/) 2.4.1 служит локальным S3. ACL в нём не поддерживается: private access обеспечен ключом и отсутствием публичного website endpoint. Production предполагает managed private S3 с подтверждённым регионом и запретом public access. Одноузловой локальный Garage не заявляется production storage.

[OpenAI data controls](https://developers.openai.com/api/docs/guides/your-data) проверены: store:false не является обещанием zero retention. Сервер отправляет только snapshot темы/целей/класса/предмета/параметров. Модель задаётся server-side OPENAI_MODEL. Для демонстрации выбрана GPT-5.4 mini: 36 подготовленных сценариев и два возрастных дополнения прошли живые автоматические проверки KK/RU/KK+RU; отдельно проверены математика, биология и пользовательский путь. Это не объявляется педагогической экспертизой или доказательством правильности любых будущих ответов. [Отчёт](../reports/live-evaluation.json).

Основные лицензии: Node/Next/React/Better Auth/docx — MIT, OpenAI SDK — Apache 2.0, PostgreSQL — PostgreSQL License, pdfplumber/openpyxl — MIT, xlrd — BSD, Tesseract — Apache 2.0, LibreOffice — MPL/LGPL. PDF adapter заменён на pypdfium2/PDFium 15 октября; PyMuPDF удалён из runtime, fixtures и QA. Garage (AGPL) применяется для локального S3; production предполагает отдельное управляемое private storage. Подробности и notices — в [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md). Это перечень зависимостей, а не юридическое заключение о лицензировании продукта.

15 октября интерфейс разделён на основной React кабинет и статический ES5 Lite. Основной кабинет откладывает загрузку редактора/форм до открытия; Lite поддерживает редактирование существующих блоков, КТП и экспорт без React. При Netlify frontend API остаётся на отдельном Compose backend. Загрузка идёт прямо в приватный S3 quarantine с последующим сканированием и публикацией нового чистого объекта; browser не получает storage credentials. Контейнеры Node используют LTS 24.22.0.

Авторизация обновлена до Better Auth 1.7.10: включён отзыв сессий после reset, проверен rollback при сбое удаления сессий и повторное использование неистраченной ссылки. Для Netlify добавлен signed gateway с отдельным секретом/site ID; это позволяет доверять provider IP после проверки подписи и не объединять пользователей в один proxy IP bucket.
