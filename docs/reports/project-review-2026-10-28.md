# Обзор проекта и проверка изменений — 28 октября 2026

Рабочий интервал: до 12:00, Asia/Qyzylorda (UTC+5). Это обзор локального проекта и его проверок; состояние публичного production, облачных аккаунтов и видимость GitHub-репозитория им не удостоверяются. Документ обновляется по мере завершения проверок.

## Карта архитектуры

| Слой | Назначение и оценка |
| --- | --- |
| `app/`, `proxy.ts` | Next.js App Router, тонкие route handlers, публичные страницы и CSP. Перед изменениями прочитана документация установленного Next.js. |
| `apps/web/components/` | React-кабинет, импорт, редакторы КТП и заданий, коллекции, восстановление черновиков. Владелец кабинета задаёт срок жизни форм и запросов. |
| `apps/web/lib/` | Авторизация, проверка владельца/Origin, PostgreSQL, приватное S3, очереди, бюджеты, потоковые скачивания. `api.ts` остаётся крупным диспетчером: последующее разделение должно сохранять точную матрицу маршрутов и общий порядок проверок. |
| `packages/contracts/`, `packages/domain/` | Zod-контракты и правила предметной области. Нормализация КТП и условия подтверждения вынесены в общий модуль `plan-review.ts`; независимые правила не должны дублироваться в интерфейсе и API. |
| `apps/worker/`, `apps/renderer/` | Долгие операции, lease/fencing и изолированный разбор документов. Renderer не получает DB/S3/OpenAI credentials. Контейнерная изоляция дополняется ограничениями разворачивания таблиц и чтения ответов. |
| `public/lite/` | Отдельный интерфейс без React, для школьных браузеров. Общие алгоритмы генерируются как ES5; персональный текст не переносится в localStorage. |
| `migrations/`, `infra/`, `.railway/` | Версионированная схема, контейнеры и конфигурация размещения. Уже применённые SQL не переписываются; новые метаданные классов вводятся отдельной миграцией. |
| `tests/`, `.github/workflows/` | Модульные, Python, браузерные и интеграционные проверки. Новые браузерные контракты можно запускать без БД; они не заменяют проверки настоящих сервисов. |

## Найдено и исправлено

1. **Известные уязвимости зависимостей.** Next.js 16.4.0 заменён на 16.4.3, Nodemailer 10.1.1 — на 10.2.1. После обновления `npm audit --audit-level=moderate` не сообщает известных уязвимостей. Это результат аудита зависимостей, а не независимого pentest. Основания: [Next.js Image Optimization](https://github.com/advisories/GHSA-2464-fhr4-w9xw), [Next.js cache](https://github.com/advisories/GHSA-673q-mjm6-r5xr), [Nodemailer address parser](https://github.com/advisories/GHSA-85x2-q946-cp5h).
2. **Устаревший аккаунт в Lite.** Все бизнес-запросы и защищённые команды входа привязаны к владельцу открытого интерфейса. Смена владельца отменяет запросы, останавливает черновик, удаляет старые формы и диалоги; отвергнутая запись не повторяется. Проверка сеанса с временной ошибкой не считается выходом.
3. **Поздний нативный ответ выхода.** До исправления реальный задержанный ответ `sign-out` первого учителя стирал cookie уже вошедшего второго. Добавлен срок жизни запросов React-кабинета и отмена при смене владельца. Уже завершённая серверная команда не откатывается. Отдельный E2E фиксирует доставку/отмену ответа и сохранность второго сеанса.
4. **Медленные коллекции.** История и библиотека раньше могли прерывать незавершённое чтение очередным resume/polling. Общий `useCollectionRead` сохраняет медленный запрос и объединяет обновления; изменение фильтра отменяет устаревшее чтение. Коллекция КТП использует тот же механизм.
5. **Целостность дат.** При сочетании `01.09.2026–2026-09-04` прежние нормализаторы теряли одну границу. Python и TypeScript теперь сохраняют исходный порядок обоих форматов и проверяются общим корпусом дат. Год не подставляется в дату без года.
6. **Казахский UTF-8.** Прежний сбор stdout мог декодировать половины многобайтной буквы отдельно. Теперь сначала собираются ограниченные байты, затем выполняется декодирование. Лимит измеряется байтами; зависший/переполняющий вывод процесс завершается.
7. **Ресурсы парсера.** Проверяются `gridSpan` DOCX, суммарное раскрытие объединённых ячеек XLS/XLSX, число сохранённых ячеек и листов, объём промежуточных таблиц и максимум 2000 уроков. Дублирующиеся части ZIP отклоняются. Отказ не обрезает документ молча. Внутренние HTTP-ответы renderer тоже читаются с лимитом фактических байтов.
8. **Интерактивная проверка КТП.** Сводка считает пропуски по всему документу; доступны фильтр и переход с фокусом к первому пропуску. Скрытые строки сохраняются. Заполненное обязательное поле не выдаётся за педагогическое одобрение. Lite показывает сводку и переход без тяжёлого клиента.
9. **Защита секретов.** Проверка границы клиентских импортов закрывает серверные зависимости, worker и явно приватные модули. Проверка публичных артефактов ищет настроенные значения credentials, включая JSON/URI-представления, и не печатает сами значения. Git-сканер расширен на другие форматы ключей, токены, скрипты и ошибочно отслеживаемые приватные конфигурации.

## Казахстанский контекст

- КТП/КТЖ рассматривается как календарно-тематический план, отдельно от краткосрочного плана урока.
- Сохраняются русский и казахский интерфейсы, казахские буквы, исходные формулировки и коды целей.
- Номер класса берётся из подтверждённого класса/явного контекста строки, а не угадывается по коду цели.
- Отказ от текста целей допустим только явно для СОР/СОЧ, БЖБ/ТЖБ. Обычный урок с одним кодом без текста не считается готовым к подтверждению.
- Программа не объявляет синтетические примеры официальным учебным планом и не подставляет непроверенный справочник целей.
- Юридическая актуальность шаблонов, регионы обработки персональных данных и фактическая конфигурация будущего production требуют отдельной проверки по официальным источникам и настройкам оператора. Настоящий обзор не является юридическим заключением.

## Проверки и границы доказательств

Первичная база: 138 модульных тестов, lint и TypeScript прошли до изменений. Docker Engine был остановлен; он запущен, существующие локальные PostgreSQL, S3, Mailpit, renderer и ClamAV подняты без удаления volumes. Перед запуском worker проверено отсутствие ожидающих задач. Проверки выполняются на синтетических аккаунтах и документах; платные AI-оценки и публичное размещение не запускаются.

Уже пройдены: реальные проверки account intent (5), коллекций и Lite (13), HTTP-границы renderer, общий корпус дат Python/TypeScript, ограничения парсера, UTF-8 и размеры ответа, проверка серверных импортов и публичных файлов. Новая проверка готовности КТП сохраняет все 30 строк, исправляет пропуск на второй странице и проходит axe для блока сводки при 360 px в обеих темах.

Одна старая проверка класса читала текст options без ожидания React-обновления при одинаковом количестве элементов. Заменена проверкой `toHaveText` с ожиданием; три повторения исходного сценария не воспроизвели продуктовый сбой. Это изменение синхронизации теста, а не ослабление ожидаемого содержимого.

Окончательные количества тестов и оставшиеся ограничения добавляются после итоговой сборки. Параллельно появившиеся изменения редактора заданий, таблиц и метаданных классов сохранены; их совместимость включается в общую проверку, а происхождение не приписывается этому аудиту.

## Остающиеся направления

- Публичный staging/production, сетевой запрет egress renderer и приватность настоящего облачного bucket пока не подтверждены этим запуском.
- Нужен разрешённый обезличенный корпус реальных школьных КТП; синтетические тесты не доказывают точность OCR на всех школьных сканах.
- Нужна предметная проверка сгенерированных заданий учителями. Автоматические проверки не доказывают педагогическую корректность.
- Старые прямые клиенты без `X-ZiyatAI-Account` сохраняют прежний контракт. Обязательность precondition для будущего rollout нужно вводить отдельно с совместимым обновлением клиентов.
- Граница клиентских модулей и сканер секретов — дополнительные инженерные проверки. Они не гарантируют отсутствие любого неизвестного формата секрета, утечек в истории Git или в сторонней инфраструктуре.
