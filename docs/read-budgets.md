# Бюджеты чтения API

Авторизованные GET/HEAD проходят через `apps/web/lib/read-budgets.ts` после проверки сеанса и удаления аккаунта, до загрузки материала, S3 или вызова renderer. Учителя с одним школьным IP используют разные бюджеты: ключ состоит из ID аккаунта и одной из четырёх фиксированных категорий. ID документа не создаёт новый бюджет.

| Категория | Маршруты | Средний темп в минуту | Допустимый начальный пакет |
| --- | --- | ---: | ---: |
| metadata | Списки КТП, история, библиотека, профиль, задания очереди, список резервных копий | 600 | 120 |
| snapshot | Полный КТП, задания и их версии, чтение резервного черновика | 120 | 12 |
| download | Исходные файлы и экспортированные документы | 30 | 6 |
| preview | Предпросмотр страницы PDF через renderer | 30 | 3 |

Это начальные настройки для запуска. Их следует уточнять по реальному использованию нескольких вкладок и ресурсоёмкости файлов. Превышение среднего темпа допустимо только в пределах начального пакета; доступ пополняется постепенно, без сброса всего лимита на границе минуты.

## Согласованность и восстановление

Миграция `011_api_read_budgets.sql` добавляет таблицу с максимум четырьмя строками на аккаунт. Ограничение GCRA выполняется атомарным `INSERT ... ON CONFLICT ... WHERE`, используя время PostgreSQL. Все экземпляры API обращаются к одному состоянию. Отклонённый запрос не переносит время следующего доступа дальше. Состояние удаляется каскадно вместе с аккаунтом.

При отказе API возвращает HTTP 429, `Cache-Control: no-store`, код `READ_LIMIT`, заголовок `Retry-After` и число секунд в JSON. Основной интерфейс и Lite показывают сообщение на выбранном языке. Ошибка чтения не завершает сеанс, не стирает поля и не отменяет уже подтверждённое сохранение. Первоначальная загрузка кабинета и редакторов имеет действие повтора. Автоматического повтора изменяющих запросов нет.

POST/PATCH/DELETE сохраняют прежние отдельные ограничения: исчерпание чтения позволяет сохранить правки или удалить аккаунт. Лимиты аутентификации Better Auth остаются отдельными. Публичные `health` и `public-config` не требуют аккаунта и не входят в эту таблицу.

## Проверки и границы

`tests/e2e/read-budgets.spec.ts` проверяет параллельные запросы к разным ID, реальное пополнение доступа по времени, отсутствие продления отказами, изоляцию аккаунтов и категорий, доступность записей и очистку при удалении. Другие сценарии проверяют повтор после отказа первой загрузки и два последовательных сохранения при исчерпанном чтении. Состояния длительного отказа в UI создаются только для собственных синтетических аккаунтов.

Ограничение частоты не заменяет глобальное ограничение памяти, потоковую передачу больших файлов, защиту публичных проверок готовности и меры хостинга против распределённой атаки. Реальная нагрузка на несколько экземпляров и настройки облачного окружения пока не проверены. Перед запуском новой версии API примените миграцию; опубликованный frontend должен включать обработку `READ_LIMIT` и повторы загрузки.
