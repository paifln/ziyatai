# Коллекция КТП

Основной кабинет использует `GET /api/ktp/collection`. Прежний `GET /api/ktp` сохраняет массивный контракт для Lite и выбора подтверждённых планов; эти клиенты продолжают запрашивать серверные страницы.

Новый ответ содержит `items`, `total`, `matched`, `counts`, `limit`, `offset`. `total` и `counts` относятся ко всем неудалённым КТП текущего пользователя; `matched` учитывает фильтры. Уроки, исходники и данные другого владельца не возвращаются. Существующая частичная индексация `plans_owner` ограничивает выборку владельцем. Изменений схемы и переписывания данных нет.

Параметры:

| Параметр | Значение |
| --- | --- |
| `q` | Название, до 200 символов; пробелы по краям удаляются. `%`, `_` и обратная косая черта ищутся буквально |
| `status` | Одно из пяти состояний КТП; отсутствие означает все |
| `grade` | Целый класс от 1 до 11; фильтрует класс самого плана |
| `sort` | `recent` (по умолчанию) или `name`; ID стабилизирует порядок одинаковых значений |
| `limit` | 1–100, по умолчанию 20; кабинет запрашивает 20 |
| `offset` | 0–1 000 000; слишком дальняя страница возвращается к последней существующей |

Страница, общие счётчики и число совпадений читаются одним SQL-запросом в общем снимке. Удалённые документы не учитываются. Текстовые параметры передаются через параметры PostgreSQL, фрагмент сортировки выбирается из фиксированного списка. Применяются авторизация, проверка удалённого аккаунта и общий metadata read budget.

При смене фильтра кабинет возвращается на первую страницу и отменяет устаревший запрос. Поиск имеет задержку 250 мс. Фоновые обновления одинакового запроса объединяются: медленный ответ не отменяется, за ним при необходимости выполняется одно повторное чтение. Уже полученная страница остаётся видимой при фоновом чтении. При уходе со страницы запрос отменяется. Ошибка сохраняет фильтры и предлагает повтор без ложного сообщения об отсутствии планов.

Переходы страниц переводят фокус на подпись результатов. Ввод поиска во время такого перехода сохраняет фокус в поле. При смене ID пользователя компонент списка создаётся заново и отменяет чтения предыдущей сессии; обычное обновление сессии того же пользователя не вызывает повторной загрузки всего кабинета. Для ручной проверки нужны более 100 планов, поиск самого старого, сочетания фильтров, удаление последних совпадений из другой вкладки, отказ сети, запоздалые ответы и смена аккаунта в другой вкладке.

Ограничения: сортировка по названию использует collation базы; метаданные класса смешанного КТП могут быть пустыми. Этот фильтр не анализирует все уроки многоклассного документа. Поддержка списка классов в метаданных требует отдельного изменения и проверки. Краткая проверка ответа и эмуляция браузера не доказывают производительность физического школьного компьютера.
