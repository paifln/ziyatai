# Коллекция КТП

Основной кабинет использует `GET /api/ktp/collection`. Прежний `GET /api/ktp` сохраняет массивный контракт для Lite и выбора подтверждённых планов; эти клиенты продолжают запрашивать серверные страницы.

Новый ответ содержит `items`, `total`, `matched`, `counts`, `limit`, `offset`. `total` и `counts` относятся ко всем неудалённым КТП текущего пользователя; `matched` учитывает фильтры. Уроки, исходники и данные другого владельца не возвращаются. Существующая частичная индексация `plans_owner` ограничивает выборку владельцем. В метаданных каждого плана возвращается `grades`: отсортированный список классов текущей версии.

Параметры:

| Параметр | Значение |
| --- | --- |
| `q` | Название, до 200 символов; пробелы по краям удаляются. `%`, `_` и обратная косая черта ищутся буквально |
| `status` | Одно из пяти состояний КТП; отсутствие означает все |
| `grade` | Целый класс от 1 до 11; ищет среди классов уроков плана, включая многоклассные КТП |
| `sort` | `recent` (по умолчанию) или `name`; ID стабилизирует порядок одинаковых значений |
| `limit` | 1–100, по умолчанию 20; кабинет запрашивает 20 |
| `offset` | 0–1 000 000; слишком дальняя страница возвращается к последней существующей |

Страница, общие счётчики и число совпадений читаются одним SQL-запросом в общем снимке. Удалённые документы не учитываются. Текстовые параметры передаются через параметры PostgreSQL, фрагмент сортировки выбирается из фиксированного списка. Применяются авторизация, проверка удалённого аккаунта и общий metadata read budget.

При смене фильтра кабинет возвращается на первую страницу и отменяет устаревший запрос. Поиск имеет задержку 250 мс. Фоновые обновления одинакового запроса объединяются: медленный ответ не отменяется, за ним при необходимости выполняется одно повторное чтение. Уже полученная страница остаётся видимой при фоновом чтении. При уходе со страницы запрос отменяется. Ошибка сохраняет фильтры и предлагает повтор без ложного сообщения об отсутствии планов.

Переходы страниц переводят фокус на подпись результатов. Ввод поиска во время такого перехода сохраняет фокус в поле. При смене ID пользователя компонент списка создаётся заново и отменяет чтения предыдущей сессии; обычное обновление сессии того же пользователя не вызывает повторной загрузки всего кабинета. Для ручной проверки нужны более 100 планов, поиск самого старого, сочетания фильтров, удаление последних совпадений из другой вкладки, отказ сети, запоздалые ответы и смена аккаунта в другой вкладке.

Перед обновлением API и worker выполните `npm run migrate`: миграция `015_plan_grades.sql` добавляет метаданные, а `migrate.ts` заполняет старые записи пакетами по 100 внутри той же транзакции, используя общие `planGrades`/`rowGrade`. Изучается только текущая версия. Явный класс строки имеет приоритет над подписью листа и общим классом. Коды целей не используются для угадывания класса. Импорт и сохранение обновляют метаданные в одной транзакции с версией. Общий класс служит запасным вариантом для строк без класса; пустые планы с общим классом сохраняют прежнее поведение фильтра. `NULL` в метаданных поддерживает старые записи, созданные прежними клиентами; до их обновления доступен фильтр общего класса. После обновления не запускайте старые API/worker, которые не поддерживают синхронизацию `grades`.

Ограничения: сортировка по названию использует collation базы. Фильтр читает готовые метаданные, не загружая уроки в браузер. Краткая проверка ответа и эмуляция браузера не доказывают производительность физического школьного компьютера.

## История заданий и библиотека

Основной кабинет читает `GET /api/history/collection` и `GET /api/library/collection` с тем же конвертом `items/total/matched/counts/limit/offset`. Прежние `/api/history` и `/api/library` по-прежнему возвращают массивы для Lite и прямых клиентов. Новые endpoints относятся к metadata read budget и проверяют владельца сеанса.

Поддерживаются буквальный поиск `q` до 200 символов, фиксированные `status`, `sort=recent|name`, `limit=1..100` и `offset=0..1000000`. Библиотека дополнительно принимает `format=docx|pdf` и `audience=student|full`; в истории эти параметры отклоняются с 422. `counts` и `total` относятся ко всей коллекции текущего владельца; `matched` учитывает фильтры. Снимки уроков, содержимое заданий, object keys и owner IDs не возвращаются. Удалённые задания и связанные с ними файлы исключаются.

Страница и счётчики вычисляются одним SQL-снимком; слишком дальняя страница возвращается к последней существующей. Это позволяет пережить удаление последнего материала в другой вкладке. Поиск откладывается на 300 мс, устаревшее чтение отменяется, повторные фоновые обновления объединяются. Ошибка чтения сохраняет фильтры и не выдаётся за пустую коллекцию.
