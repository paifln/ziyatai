# Браузеры и слабые школьные компьютеры

ZiyatAI не требует установки Node, Docker, OCR или офисного пакета **на компьютере учителя**. Их использует сервер. Клиенту нужны браузер и соединение с сайтом.

## Два интерфейса

| Режим | Назначение | Что загружается |
| --- | --- | --- |
| Основной `/` | Полный редактор, версии, настройки оформления | React/Next, затем редактор и формы по необходимости |
| Лёгкий `/lite/` | Вход, импорт и проверка КТП, генерация, редактирование существующих заданий и выпуск документов | Статический HTML, один небольшой JS и CSS; без React, внешних шрифтов и постоянного опроса |

Основной интерфейс следует минимумам установленного Next.js: Chrome/Edge 111+, Firefox 111+, Safari 16.4+. Для более ранних распознанных версий ранний ES5 script переводит на Lite до зависимости от hydration. Строки восстановления пароля сохраняются при переходе. [Next.js browser support](https://nextjs.org/docs/architecture/supported-browsers).

Lite написан в синтаксисе ES5, использует XMLHttpRequest, FormData, URLSearchParams и crypto.getRandomValues. Наличие этих возможностей проверяется перед входом. Internet Explorer не поддерживается; вместо пустого экрана выводится понятное сообщение. ES5-синтаксис — необходимая проверка, но сам по себе не доказательство работы каждого старого браузера.

## Реальные проверки

На текущем Windows-хосте пройден сценарий в **настоящем 32-битном Firefox ESR 115.40.0** через geckodriver 0.35.0: вход через форму, основной кабинет, Lite, загрузка DOCX, исправление метаданных, подтверждение КТП, редактирование задания, отметка проверки учителем и выпуск DOCX. Использованы отдельные скачанные бинарники и временный профиль; системная установка Firefox не менялась. [Отчёт](reports/legacy-browser.json).

Firefox ESR 115 относится к ветке с поддержкой Windows 7. Проверены официальный SHA256 установщика и подпись Mozilla; совместимость driver 0.35.0 с ESR 115 указана в документации Mozilla. [Требования Firefox 115](https://www.mozilla.org/en-US/firefox/115.0esr/system-requirements/), [geckodriver support](https://firefox-source-docs.mozilla.org/testing/geckodriver/Support.html).

**ОС Windows 7 и физический школьный ПК в этом прогоне не использовались.** Их TLS/root certificates, шрифты, драйверы и фактическую скорость нужно проверить на месте. Современный Chromium отдельно проверен на ширинах 360, 768 и 1440 px; проверяются отсутствие overflow, клавиатура, Escape, доступность WCAG A/AA и защита несохранённых правок.

Дополнительно пройдены **7 сценариев в Playwright WebKit 27.2**: адаптивность и доступность, меню/несохранённые правки, большая таблица, Lite и полный UI import/edit/DOCX на desktop/phone/tablet. Проверены ширины 360/768/1440 и сенсорные viewport 390×664 / 810×1080; получение настоящих сгенерированных `touchstart` событий проверяется во время навигации. В mobile UA указан iOS минимум 16.4 для открытия основного UI; сам движок — WebKit 27.2 на Windows. Это не проверка Safari 16.4 или физического iPhone/iPad. [Отчёт WebKit](reports/webkit-browser.json).

## Производительность

[Отчёт](reports/browser-performance.json) измеряет compiled production build при симуляции CPU slowdown ×6 и сети 1,6 Mbps down / 750 Kbps up / 150 ms latency. Это лабораторная симуляция, не публичный CDN и не физический старый процессор. Lite передаёт около 11 KB JavaScript и показывает основной контент примерно за 1,1–1,2 секунды, основной интерфейс — примерно за 2,8–3,2 секунды. На общем Windows-хосте была фоновая активность; snapshot CPU в начале — 49%, нагрузка не поддерживалась постоянной. Точные значения, digest образа и версия браузера находятся в отчёте; это отдельные прогоны стартовых страниц без входа, а не статистический production benchmark.

В простое кабинет не опрашивает бизнес-API. Опрос включается только для незавершённой операции; скрытая или offline вкладка приостанавливает его. Обновление по возвращении и кнопке сохраняется. Большие КТП показываются по 25 строк, Lite — по 10. В редакторе формы создаются для открытого задания, остальные показывают краткое условие. Таблицы заданий также редактируются по 10 строк: для таблицы 200×20 одновременно создаются 220 полей вместо 4020. Переход страницы не удаляет данные; экспорт использует полную таблицу.

## Повторный прогон

```powershell
npm run build
npm run start
npx tsx scripts/browser-check.ts
npx playwright test tests/e2e/design.spec.ts
```

Полные прогоны запускайте последовательно с паузой не менее 60 секунд после предыдущего. Ограничение авторизации остаётся включённым: одновременные/частые повторы с общего localhost IP могут получить штатный HTTP 429.

Повтор WebKit проверки в PowerShell:

```powershell
npx playwright install webkit
$env:QA_BROWSER = 'webkit'
npx playwright test tests/e2e/design.spec.ts tests/e2e/ui.spec.ts --grep 'large plans|both sign-in|workspace stays|lite imports|teacher UI'
Remove-Item Env:QA_BROWSER
```

Для необязательного Firefox-прогона извлеките официальный win32 Firefox ESR 115.40.0 без системной установки в `.local/browsers/firefox115/core` и geckodriver 0.35.0 в `.local/browsers/geckodriver`. Сверьте SHA256 с Mozilla и цифровую подпись, затем запустите `npx tsx scripts/legacy-browser-check.ts`. Другие пути задаются `LEGACY_FIREFOX` и `LEGACY_GECKODRIVER`. Тест создаёт только синтетический аккаунт с письмами в локальном Mailpit.
