# Модель угроз

Недоверенные данные: документы учителей, ячейки КТП, ответы AI, редактируемый AST, UUID и запросы браузера. Владельца определяет серверная сессия; email, user metadata и `owner_id` из формы не дают доступа к материалам.

| Угроза | Защита | Границы |
| --- | --- | --- |
| Чужие материалы | Проверка владельца и tombstone на API, jobs, исходниках и экспортах; приватная схема и bucket | Прямые grants и конфигурация Supabase требуют контроля при развёртывании |
| Смена аккаунта в другой вкладке | Захваченный ID кабинета, `X-ZiyatAI-Account`, отказ `SESSION_CHANGED` | Заголовок не credential; детали в [контракте](account-intent.md) |
| Кража сессии и CSRF | HttpOnly/SameSite cookies, Secure на HTTPS, точный Origin, реестр отзыва и лимиты | Регистрация без проверки email не доказывает владение почтой; импортированные аккаунты защищены от присвоения по совпадению email |
| Подмена proxy | Подпись Netlify, site ID и доверенный IP только после проверки | Quick Tunnel временный; публичный backend должен сохранять проверку подписи |
| Script injection | Nonce CSP и React text rendering, строгий AST без HTML | Автотесты не заменяют независимый pentest |
| Вредоносные документы | Размер, allowlist, сигнатура, ZIP/XML/PDF проверки, ClamAV, quarantine | Недоступный антивирус закрывает доступ; полное обнаружение вредоносных файлов не гарантируется |
| Ошибка parser/LibreOffice | Отдельный renderer без DB/S3/AI ключей, token, read-only root, tmpfs и лимиты ресурсов | Локальный Docker и будущий Railway требуют проверки сети и образов |
| Prompt injection и ошибка AI | Источник отделён от инструкций, нет tools, строгая схема, лимиты repair и явная проверка учителя | Schema не доказывает педагогическую и фактическую правильность |
| Повтор фоновой операции | Транзакция enqueue, idempotency, lease fencing, heartbeat и проверка перед публикацией | Внешний AI не гарантирует exactly once |
| Гонка удаления | Tombstone, отмена задач, проверка перед публикацией и повторяемая очистка S3 | Физическое удаление требует работающего worker |
| Истощение ресурсов | Лимиты тела/документа, бюджеты чтения/AI, ограничение буферизации и сроки внешних вызовов | Распределённая нагрузка и лимиты хостинга проверяются отдельно |
| Утечка ключей | Нет NEXT_PUBLIC secrets, серверная граница модулей, сканирование исходников и публичной сборки | Локальные env и backups остаются ответственностью оператора |

Модульные и интеграционные проверки находятся в `tests/`; CI использует изолированный Supabase. Свежесть зависимостей и образов проверяется при выпуске, а не подтверждается удалённым историческим отчётом. Ротация и резервирование описаны в [runbook](runbook.md).
