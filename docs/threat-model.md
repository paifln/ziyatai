# Модель угроз и защита

Недоверенные входы — загруженные документы, текст ячеек, source snapshot, ответы модели, редактирование AST и UUID в URL. Авторизованный субъект определяется только сессией Better Auth. owner_id нельзя передать через пользовательскую форму.

| Угроза | Реализация | Проверка и остаточный риск |
| --- | --- | --- |
| Чужие ресурсы и storage keys | Проверка owner и tombstone на API, jobs, исходниках, export и parent generation | E2E с двумя аккаунтами: чужие КТП, генерация и download дают 404. Приватность bucket требует отдельной проверки конфигурации production. |
| Старый интерфейс после смены cookies | Основной React-кабинет фиксирует ID владельца бизнес-запросов и трёх нативных команд SDK; backend сравнивает X-ZiyatAI-Account с настоящей сессией. При несовпадении — 409 и каноническая проверка без повтора записи. Нативный rate limit действует до auth-плагина; проверка не продлевает сеанс | Проверены профиль, удаление аккаунта, смена пароля, revoke-other-sessions и sign-out при задержанном get-session. Заголовок не является credential. Старые клиенты без него, Lite и доставка Set-Cookie из уже отправленного auth-ответа требуют отдельного аудита. Контракт: account-intent.md. |

Обычные пользовательские ссылки PDF разрешены. ClamAV недоступен — fail closed. Нельзя обещать обнаружение всех вредоносных файлов. |

| Prompt injection | System/developer инструкции отделены от source data, нет tools, передаётся минимальный snapshot, строгий AST без HTML | Mock regression подтверждает разделение. Живые предметные примеры проходят; полноценный adversarial AI eval ещё не проведён. |
| Ошибки AI | Schema с точным числом задач и snapshot ID + ссылки + уровни + баллы + дубликаты + числа перевода + ограниченная арифметика + время по уровню; max 2 repair; всегда needs_review | Живые synthetic примеры проверены. Арифметический grammar не доказывает соответствие всех условий ответам. Учитель обязательно проверяет содержание. |

Next dev пишет query token в диагностический access log; он предназначен только для localhost. Production не включает access logging с query strings. |

Дополнительное локальное усиление 28 октября 2026 года: общий срок чтения JSON/multipart — 60 секунд; сборщик не удерживает отдельный объект на каждый сетевой фрагмент. Внутреннее чтение S3 ограничивает реальные байты до выделения полного буфера; запись, метаданные и очистка имеют сроки ожидания. Проверки multipart и PDF preview используют общий бюджет двух одновременно буферизуемых операций. Это ограничение обработки, а не полная гарантия объёма памяти всех медленных исходящих HTTP-ответов.

ClamAV получил отдельный транспорт с общим сроком 60 секунд, последовательной отправкой и точной проверкой ответа. Renderer ограничивает чтение заголовков до авторизации и отвергает неоднозначное HTTP framing; его клиент запрещает redirect и произвольные коды ошибок. OOXML проверяется по самим URI связей, даже если внешний адрес помечен как Internal. PostgreSQL переживает разрыв собственных соединений, а неудачный rollback исключает соединение из пула.

Физическая очистка удаляет указатели только на уже обработанные ключи S3: поздние tombstones сохраняются для следующего прохода. Они продолжают занимать квоту загрузок до физической очистки. Экспорт использует ключ отдельной попытки worker, поэтому запоздалая очистка старого lease не удаляет новую публикацию. Общая очередь проверяет соответствие повторного ключа типу, ресурсу и payload; резерв AI учитывает размер исходных данных и заменяемого задания. Подробные проверки и оставшиеся ограничения: [отчёт 28 октября](reports/security-hardening-2026-10-28.json).

Ротация ключей и восстановление описаны в runbook. Полноценный независимый pentest, юридическая оценка, подтверждение регионов и production мониторинг остаются условиями запуска, а не подразумеваются успешной локальной сборкой.
